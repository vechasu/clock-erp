# Миграция единого каталога

Миграция `unified_catalog_v1` добавляет стабильные ID брендов и категорий,
ссылки из товаров, продаж и приходов, локальный журнал приходов и расширенную
историю движений. Она не объединяет карточки товаров по похожему названию и не
меняет остатки.

Перед применением скрипт создаёт проверенную SQLite-копию, затем сравнивает
количество карточек и сумму остатков до и после. Точные варианты регистра и
пробелов связываются с одной записью справочника. Неоднозначные товары и
исторические JSON-записи выводятся отдельно и остаются без автоматического
объединения. Точные однозначные совпадения сохраняются в
`erp_legacy_catalog_links`; сомнительные — в
`erp_legacy_catalog_ambiguities` со статусом ручной проверки. Исходные JSON-файлы
не переписываются.

Безопасная предварительная проверка:

```bash
venv/bin/python scripts/migrate_unified_catalog.py \
  --database instance/catalog.db
```

Применение после общего production-backup:

```bash
venv/bin/python scripts/migrate_unified_catalog.py \
  --database instance/catalog.db \
  --backup-dir /opt/clock-erp-backups/catalog-migrations \
  --apply
```

Повторный запуск защищён маркером `unified_catalog_v1`. Для отката нужно
остановить сервис, сохранить проблемную базу для расследования, восстановить
SQLite-файл из указанной в отчёте копии и вернуть предыдущий commit приложения.
