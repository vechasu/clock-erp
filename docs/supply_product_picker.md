# Product Picker: товары и поставки

## Проверенная цепочка UI → API → service → DB

- «Товары»: `warehouse.html` → общий `product-picker.js` (поиск/preview) → `/api/v1/bitrix-products/search`, `/<id>`, `/<id>/import` → `BitrixCatalogReadOnlyClient`, `BitrixERPProductSync.apply_single`, `ProductImageStore` → `catalog_excel_products`, справочники брендов/категорий, локальное фото. Существующие create/update и переход в каталог сохранены.
- «Приход»: `supplies.html` / `supplies.js` → тот же picker и Bitrix API; ERP-поиск использует `/api/v1/catalog/options?type=product`. Импорт передаёт `supply_id`: сервер проверяет существование/статус поставки и права, затем выбирает внутренний режим `resolve` существующего импортера. Идентификация: Bitrix ID, прежняя связь с `catalog_products`, затем артикул; неоднозначные, удалённые и конфликтующие карточки отклоняются. Новая карточка получает stock=0, существующая сохраняет свой остаток и поля.
- После импорта ERP ID → `POST /api/v1/receipts/supplies/<id>/items` → `SupplyEngine.add_item` → `erp_receipts`, `erp_receipt_items`. Существующий ключ идемпотентности сохраняется в sessionStorage, повтор использует тот же ключ и тело. Одинаковые товары объединяются в одну строку.
- Изменение количества черновика: `PATCH /api/v1/receipts/supplies/<id>` → `SupplyEngine.update`. Проведение: `POST .../post` → `SupplyEngine.post` → `ReceiptInventory._post_draft` → баланс и `catalog_stock_movements`. Добавление в проведённую поставку использует прежний `SupplyEngine.add_item`: отдельное движение дополнения, без изменения истории.
- «Было / Приход / Станет»: `SupplyEngine._get` использует текущий баланс черновика или исторические движения проведённой поставки. Фото позиции предпочитает сохранённый локальный файл.

## Частичный успех и ограничения

Импорт карточки и добавление позиции остаются отдельными операциями. При ошибке добавления интерфейс сообщает, что карточка сохранена, но добавление не подтверждено; повтор не импортирует её заново и сохраняет ключ операции. Внешних записей в Bitrix или МойСклад нет. Миграций и изменений конфигурации нет. Продажи не изменены.

Проверки используют временные БД и fake Bitrix; реальные приходы для smoke не создаются. Проверены существующий импорт Products, карточка со всеми полями/фото, нулевой остаток нового товара, существующий товар, повтор импорта/добавления, объединение позиций, reload, проведение и дополнение, сбой импорта/добавления, недопустимые количества. Интерфейс проверен DOM-тестами без браузера; визуальная проверка в браузере не выполнялась по правилам проекта.

Откат: revert коммита через PR и штатный deploy; карточки/поставки, созданные пользователями, сохраняются, обратной миграции нет.
