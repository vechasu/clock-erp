# Кандидаты архитектурных решений

В этом разделе пока нет принятых ADR. Техническая реализация сама по себе не
доказывает управленческое решение. Ни один кандидат ниже не считается
`accepted`, пока владелец не подтвердит формулировку, контекст и границы.

| Кандидат | Подтверждено кодом | Подтверждено документами | Неизвестно | Рекомендуемый статус | Решение владельца |
| --- | --- | --- | --- | --- | --- |
| ERP как источник истины | Нет: данные распределены между SQLite, JSON, файлами, Bitrix и МойСклад | Старый React-аудит прямо фиксирует отсутствие единого источника истины | Какая система authoritative для товара, остатка, заказа и финансового события | `proposed` только после определения data ownership | Утвердить владельца данных отдельно для каждой сущности либо отклонить общую формулировку |
| Jinja + React | Jinja обслуживает ERP; `frontend/` содержит Vite/TypeScript build marker, но не React pages | Исторические `full-react-rewrite-*` описывают гибридный этап, который не равен текущему состоянию | Является ли гибрид целевой архитектурой или временным следом старой программы | `proposed` | Подтвердить целевую роль frontend build и срок/условия сосуществования |
| Единая дизайн-система | Есть theme tokens, `erp-components.css`, shared shell, modal, pagination, combobox и notifications; page-specific CSS остаётся | Историческая UI-карта предлагает унификацию, но не является решением | Какие примитивы нормативны и допустимы ли локальные исключения | `proposed` | Утвердить источники tokens/components и порядок исключений |
| Серверная пагинация | Реализована для основных Jinja-списков и JSON API, но journal использует cursor, а пределы API различаются | Performance-аудит и React-планы поддерживают подход, но относятся к старым baseline | Нужен ли единый contract page/page_size/per_page и где обязателен cursor | `proposed` | Утвердить contract по типам списков, не объявляя одну схему универсальной |
| Private S3-compatible off-site backups | В репозитории не найден S3 client или off-site backup implementation; `scripts/deploy.sh` создаёт локальный production backup | Старые React roadmap/risk documents упоминают off-site backup как будущую защиту | Провайдер, шифрование, retention, restore rehearsal и фактическое наличие | `proposed` | Подтвердить необходимость и операционные требования либо снять кандидата |

После подтверждения решение оформляется по
[шаблону ADR](../templates/adr.md). Если формулировка не отражает фактическое
решение, кандидат удаляется или уточняется без создания ADR.
