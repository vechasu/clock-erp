# Аудит единой обратной связи ERP

## Охват

Глобальный `VechasuNotify` подключён через `_sidebar.html`, поэтому один менеджер
работает на всех активных ERP-экранах: товары, продажи (Tictactoy, WB, Amazon),
приход, настройки, отчёты и Excel-сценарии. Менеджер перехватывает только
изменяющие `fetch`-запросы (`POST`, `PUT`, `PATCH`, `DELETE`); навигация, поиск,
фильтры и GET-запросы уведомлений не создают.

## Карта изменяющих операций

| Область | Frontend | Backend | Результат |
| --- | --- | --- | --- |
| Товары | формы добавления/редактирования, bulk, фото, удаление, catalog combobox | `/api[/v1]/products*`, `/warehouse/*`, `/products/*` | loading → success/error; HTTP 207 и массив `errors` → warning |
| Бренды и категории | catalog combobox и формы прихода | `/api[/v1]/brands*`, `/api[/v1]/categories*`, `/receipts/catalog/create` | создание/изменение/удаление с предметным текстом |
| Продажи Tictactoy/WB/Amazon | форма продажи, отмена, возврат, удаление, статус | `/api[/v1]/sales*`, `/sales/*` | loading → подтверждённый success/error; канал остаётся частью карточки продажи |
| Приход | создание, редактирование, отмена, фото, Excel-проведение | `/api[/v1]/receipts*`, `/receipts/*`, `/products/receipts/*` | результат после ответа; redirect-сообщение переносится на целевую страницу |
| Ремонты | CRUD, статус, архив/restore, накладные, вложения | `/api[/v1]/repairs*` | единый жизненный цикл уведомления |
| Настройки и доступ | настройки ERP, приглашения, отзыв приглашения | `/api/v1/settings`, `/settings`, `/settings/invitations*` | loading → success/error; «нет изменений» — info без запроса |
| Склад и каталог | ячейки, остаток, архив, сопоставление | `/warehouse/*`, `/catalog/mapping/confirm`, `/products/*/match` | единый feedback после серверного результата |
| Интеграции | Bitrix/МойСклад через операции товаров, фото, продаж и прихода | соответствующие API/legacy endpoints | 5xx/сеть не становятся success; `partial_success`, warnings, HTTP 207 становятся warning |

## Контракты и совместимость

- API success распознаётся только по успешному HTTP-ответу без `error`.
- 400/401/403/404/409/413/422/500+ и network/timeout преобразуются в понятный текст.
- Необработанные API-исключения логируются сервером и возвращают безопасный JSON
  `INTERNAL_ERROR`, без stack trace и HTML.
- Старые redirect-параметры `notice/message` и верхние `.notice` мигрированы в toast;
  inline-валидация полей и сообщения внутри форм сохранены.
- На массовых операциях один toast агрегирует `updated/errors`; одновременно видно
  максимум три уведомления, остальные ждут в очереди, дубликаты объединяются.
- Менеджер поддерживает action-кнопку, progress, обновление существующего toast,
  ручное закрытие и перенос результата через redirect.
