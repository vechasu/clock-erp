# Финальное завершение ремонта

Аудит до изменения: `instance/repair_cases.json`, схема v4, запись под `fcntl.flock`
через `mutate_repair_file`. SQL-таблицы repairs нет. HTML относил к архиву
`archived_at` либо `status in {completed, cancelled}`, API — только `archived_at`.
Действие `complete` устанавливало `completed`, `location=delivered` («Выдан клиенту»),
`completed_at`, но не архивирование. История — существующий массив `history`.

Теперь новые завершения атомарно сохраняют `completion_result`, `completion_comment`,
`completed_at` (секунды и часовой пояс), `completed_by`, `archived_at`, `archived_by`.
Стоимость использует существующее историческое поле `final_cost`; согласованная цена
`agreed_cost` и полученная оплата `payment_amount` не подставляются в модалку.
Пустая стоимость не заменяет сохранённую, ноль допустим.

Три новых результата: repaired, impossible, customer_declined. Прежние значения
сохранены в словаре для отображения истории, но запрещены для нового завершения.
Отремонтированный товар закрывается из ready_return (самовывоз/другое) или
outbound_transit (подтверждение получения). Отказ и невозможность также доступны
из diagnostics/waiting_decision; местонахождение при этом не выдумывается.
Повторное завершение, включая конкурентные запросы, возвращает 409 без нового события.

Миграция аддитивная при чтении: пустые defaults для completed_by/final_cost,
версия JSON остаётся v4, физическое переписывание файла при deploy не требуется.
Старым архивам не назначаются вымышленные результат, автор или дата. API и HTML
используют одинаковое определение архива. Противоречивые старые записи вроде
new + delivered по-прежнему требуют уточнения, их статус не исправляется по догадке.

Проверки: изолированные JSON/БД, backend lifecycle/archive/completion/workflow,
конкурентные запросы, существующий Playwright smoke (включая обязательный select,
submit, закрытие модалки, счётчики, архив), адаптивные размеры 1440/768/390.
Реальные ремонты для проверки не используются.

Откат: вернуть предыдущий код штатным deploy. Новые поля совместимы со старым
JSON reader; архивные записи и история не удаляются. Конфигурация не меняется.
