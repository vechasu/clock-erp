# Складские списания

`/app/sales?source=writeoff` — отдельный журнал; `erp_sales` и финансовые KPI не используются. API: GET/POST `/api/v1/writeoffs`, POST `/api/v1/writeoffs/<id>/cancel` (также `/api/…`). Права: admin/employee, штатные auth и CSRF. Причина обязательна; для «Прочее» обязателен комментарий. Повтор POST с тем же Idempotency-Key возвращает документ, несовместимый payload отклоняется.

Миграция `2026-09-08-stock-writeoffs-v1` добавляет `erp_writeoffs` и `erp_writeoff_items` через существующий deploy-time migration ledger. Второй остаток не создаётся; данные существующих таблиц не изменяются. Полная схема проверяется отдельным добавочным manifest. Runtime не выполняет DDL.

Создание и отмена выполняются под `BEGIN IMMEDIATE`: актуальный остаток, блокировка инвентаризации, документ, остаток, движение и аудит в одной транзакции. Используются штатные `balance`/`write_balance`/`physical_lines`. Для сборных SKU сохраняются списанные компоненты и принадлежность физическому балансу; отмена использует этот снимок даже после изменения состава. Неподтверждённый физический остаток отклоняется. Повторная отмена не создаёт движений.

Движения записываются в `catalog_stock_movements` с `movement_type=manual_adjustment`, однозначным `source_type=writeoff`, ID документа и `operation_kind=post/cancel`. История показывает «Списание» / «Отмена списания». Это позволяет не перестраивать существующую таблицу движений SQLite 3.7.17. Централизованный аудит содержит изменения stock для товаров, ID списания, автора и причину. В журнале сохраняются авторы создания/отмены и снимки названия, артикула, бренда и категории.

Проверки: `python3 scripts/run_backend_tests.py --pattern test_writeoffs.py`; регрессия sales; `scripts/check_runtime_ddl.py`; static migration compatibility; Playwright `e2e/writeoffs.spec.ts` на desktop/mobile. Все записи выполняются только в временные тестовые БД, внешняя сеть в backend runner отключена.

Развёртывание: штатный `scripts/deploy.sh` с backup, репетицией миграции, остановкой сервиса, применением миграции и read-only smoke. Откат — штатный rollback с проверенной резервной копией БД при остановленном сервисе; после реальных новых операций нельзя восстанавливать старую копию без сохранения новых данных. Один откат кода недостаточен: предыдущая версия отклонит незнакомую миграцию в ledger.
